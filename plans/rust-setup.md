# Rust setup

Bring the Rust workspace in line with the other Rust projects: a pinned nightly toolchain, cargo-deny, a rustfmt config, shared dependency versions, the unsafe and Debug lints, and Clippy's `pedantic` and `nursery` groups.

Status: plan only. Nothing here is built yet.

## How to read this plan

- Each step is one commit, made in the order written, with a one-line message and the Co-Authored-By trailer. The Clippy lints are one commit each (Steps 6–64).
- Step 1, the setup commit, runs no lint, format or tests: it only adds the configs and docs, and its `rustfmt.toml` would fail the format check until Step 2 reformats.
- Every commit from Step 2 on passes `bun run typecheck`, `bun run lint:fix`, `bun run format:fix` and `bun run test`. That is why the Clippy groups go on with temporary allows (Step 5) and each lint's commit removes its own.
- Each step updates `AGENTS.md` for what it changes, in the same commit, so the rules always describe the code as it is.
- Counts were measured on 2026-11-01 with the 2026-10-24 nightly (`cargo clippy --workspace --all-targets`, no allows). Step 5 measures them again on the pinned nightly before it starts, and the table in Steps 6–64 follows that measurement.

## Step 1: toolchain, cargo-deny, rustfmt config and docs

This commit runs no lint, format or tests (see How to read this plan).

1. `rust-toolchain.toml` at the root:

   ```toml
   [toolchain]
   channel = "nightly-2026-10-29"
   components = ["rustfmt", "clippy"]
   profile = "minimal"
   ```

2. `rust-version = "1.101"` in `[workspace.package]`, and `rust-version.workspace = true` in every crate's `[package]`.
3. `.github/workflows/build.yml`: the three `dtolnay/rust-toolchain@stable` steps become `dtolnay/rust-toolchain@master` with `toolchain: nightly-2026-10-29` (the checks job keeps `components: clippy, rustfmt`). A later move of the pin changes this date and `rust-toolchain.toml` together.
4. `deny.toml` at the root:
   - `[graph] all-features = true` and `targets` set to the five platforms Opsis ships: `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-pc-windows-msvc`, `aarch64-apple-darwin`, `x86_64-apple-darwin`.
   - `[advisories] version = 2`, `db-path = "~/.cache/opsis-advisory-db"` (55 MB), `yanked = "deny"`.
   - `[licenses] version = 2` with the licences the dependency graph uses on those platforms, all GPL-3.0-compatible: `0BSD`, `Apache-2.0`, `Apache-2.0 WITH LLVM-exception`, `BSD-2-Clause`, `BSD-3-Clause`, `BSL-1.0`, `bzip2-1.0.6`, `CC0-1.0`, `GPL-3.0-or-later` (the workspace's own crates), `IJG`, `ISC`, `MIT`, `MIT-0`, `MPL-2.0`, `Unicode-3.0`, `Unlicense`, `Zlib`. A draft with these targets passed `cargo deny check licenses` with every entry used.
   - Without the targets, two more licences come in from crates Opsis never builds: `CDLA-Permissive-2.0` from `webpki-root-certs`, which `rustls-platform-verifier` uses only on `wasm32`, and `NCSA` from `libfuzzer-sys`.
   - The draft run found six unmaintained crates and no vulnerabilities, the same with and without the targets. None has a safe upgrade, so each is an `ignore` entry with a `reason` field:

     | Advisory          | Crate              | Comes from                                                                                              |

     | RUSTSEC-2024-0370 | `proc-macro-error` | `glib-macros` 0.18, the GTK 3 stack under the Linux webview                                             |
     | RUSTSEC-2024-0436 | `paste`            | `specta` 2.0.0-rc.26 (pinned), and `pulp` and `rav1e` under `image`                                     |

5. A `lint:deny` script, `cargo deny check advisories licenses`, added to `lint` and `lint:fix` beside `lint:rust` (with its `//#lint:deny` task in `turbo.json`, not cached). CI installs cargo-deny 0.19.8 in the checks job (`taiki-e/install-action` with `tool: cargo-deny@0.19.8`) before `bun run lint`.
6. `rustfmt.toml` at the root:

   ```toml
   group_imports = "StdExternalCrate"
   imports_granularity = "Module"
   use_field_init_shorthand = true
   ```

   - rustfmt's own defaults are `group_imports = "Preserve"`, `imports_granularity = "Preserve"`, `reorder_imports = true` and `use_field_init_shorthand = false`; `max_width` is already 100 and the edition (and with it the 2024 style) comes from `Cargo.toml`.
   - `group_imports` and `imports_granularity` are unstable rustfmt options: the pinned nightly applies them, stable rustfmt would skip them.
   - Measured with `cargo fmt --check`: these settings change 50 files, because most imports are already grouped std, external, crate and written one module per `use`. `imports_granularity = "Crate"` would rewrite 386 files instead. Field shorthand changes nothing today.

7. `AGENTS.md`:
   - Tooling: the pinned nightly and how to move it (`rust-toolchain.toml`, the date in `build.yml`, `rustup default`, agent-os's pin).
   - Verify with: `lint` and `lint:fix` run cargo-deny.
   - Licences: the allow-list lives in `deny.toml`, for the five platforms Opsis ships, and the list of compatible licences gains the ones above; an ignored advisory needs a `reason`.
   - Imports are grouped std, external, then the workspace's own, one `use` per module, and rustfmt keeps them so.

## Step 3: workspace dependencies

1. `[workspace.dependencies]` in the root `Cargo.toml`:
   - Every workspace crate as a path entry (`opsis-types = { path = "crates/types" }`…).
   - Every external crate once, at its loose major: `"1"` for crates at 1.0 or later, `"0.<minor>"` for 0.x crates. Exact pins stay exact: `specta = "=2.0.0-rc.26"`, `tauri-specta = "=2.0.0-rc.26"`, `specta-typescript = "=0.0.13"`, `specta-serde = "=0.0.13"`.
   - The root entry carries only the features every crate that uses it needs, and `default-features = false` wherever any crate turns them off (as `sqlx` does), because the root's features are a minimum that crates can't remove. Crates add their own (`tokio` has 12 different feature sets today).
2. Every crate's dependencies become `dep.workspace = true` or `dep = { workspace = true, features = [...] }`, in `[dependencies]`, `[dev-dependencies]` and `[build-dependencies]`.
3. `Cargo.lock` doesn't change: loosening `"1.0.229"` to `"1"` keeps the version already locked. `git diff Cargo.lock` is empty at the end of the step.
4. `AGENTS.md`, the dependencies paragraph:
   - `cargo add -p <crate> <dep>` reuses a dependency already in the root table.
   - A new dependency needs one hand edit, its pin in the root `[workspace.dependencies]`; that is the only dependency block edited by hand.
   - Versions are loose majors; `Cargo.lock` holds the exact one, and adding or updating a dependency still takes the latest release.
   - The specta pins sit in the root table, moved together as before.

## Step 4: Rust lints

1. `[workspace.lints.rust]` with `unsafe_code = "deny"` and `missing_debug_implementations = "warn"`.
2. `unsafe_code` fires nowhere today: no crate has `unsafe`.
3. `missing_debug_implementations` fires 118 times. Each type derives `Debug`, or gets a written `Debug` with `finish_non_exhaustive` where a field has none (handles, channels, trait objects).
4. `plans/terminal.md`:
   - Decisions, Crates: `opsis-vt`'s `lib.rs` starts with `#![allow(unsafe_code)]` beside its `#![deny(unsafe_op_in_unsafe_fn)]`.
   - `opsis-terminal` loses its `#![forbid(unsafe_code)]` and the test that reads its sources for `unsafe`; the workspace `deny` covers it.
   - Tests and the `AGENTS.md` paragraph it plans say the same.
5. `AGENTS.md`: `unsafe` is denied workspace-wide and allowed only in `opsis-vt`; every public type implements `Debug`.
