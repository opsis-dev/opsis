# Workspace

The repository follows the layout of `ctf-platform`: JS/TS apps in `apps/`, JS/TS packages in `packages/`, and all Rust in `crates/`, one crate per domain. Bun workspaces (`apps/*`, `packages/*`) and turbo run the TS side; a Cargo workspace (root `Cargo.toml` listing `crates/*`, `Cargo.lock` at the root) runs the Rust side. `src/shared` stops existing: every file goes to the one place that owns it, and what two sides need is either generated from Rust or kept small and tested on both sides.

## What it adds

- Each part builds with its own tool and ships only what it imports: the editor with Vite, the video bundle with Remotion's bundler (Rspack), the sidecar with `bun build`, the crates with `cargo` (the app through the Tauri CLI).
- An app is built and nothing imports it; a package is source an app compiles; a crate owns one domain and depends only on the crates below it.

## Fit with Opsis

Already in place:

- `src/shared` is runtime-neutral by rule (oxlint forbids `node:*`, `electron`, `playwright-core`, `@remotion/renderer`, `@remotion/bundler` there), so its files can move without untangling Node code.
- Bun is already the package manager.
- `src/video` and `src/renderer` already only meet through `src/shared`, apart from two imports: `registerFaces`/`unregisterFaces` (`src/renderer/fonts/library.ts`) and `designScaleFor` (`src/renderer/editor/live-view.tsx`).

Missing:

- `crates/` and the Cargo workspace (phases 1 and 1.5 built the TS side).

## Work

1. **Workspace (done, phases 1 and 1.5).** Bun workspaces `apps/*` and `packages/*`, turbo with `build`, `typecheck`, `lint`, `test` per member and the Electron app's tasks at the root (`typecheck:app`, `lint:app`, `test:app`).
2. **Move without changing behaviour (done, phase 1).** `src/renderer`, `src/video` and `src/worker/render` moved, `src/shared` split by consumer, with the Rust-bound files in `packages/core`.
3. **The two UI→video imports (done, phase 1).** `registerFaces`/`unregisterFaces` and `designScaleFor` come from `video/spec`.
4. **Tool configs per member (done, phase 1).** Each has its own `tsconfig.json`, `vitest.config.ts` and `oxlint.config.ts`; the video rules stay in `packages/video`.
5. **Cargo workspace (phase 2).** Root `Cargo.toml` with `[workspace] members = ["crates/*"]` and `resolver = "3"`, `Cargo.lock` at the root, `target/` ignored. Each crate is added in the phase that builds it, in `crates/<domain>` with the name `opsis-<domain>` (**The crates**). `opsis-desktop` is created in `crates/desktop` with the Tauri CLI in phase 6; its `tauri.conf.json` points `frontendDist` at `apps/ui`'s build, `beforeDevCommand` and `beforeBuildCommand` at `apps/ui`'s Vite scripts, and `bundle.externalBin` at the sidecar build. Turbo's `build` makes `apps/ui` and the video bundle before `cargo tauri build`.
6. **Retire `packages/core`** in phase 6, when the editor reads generated types and Rust results and nothing imports it.

## Phase 1 as built

Steps 1 to 4 are done (2026-10-25, branch `feat/tauri`); the app still runs on Electron from the root.

- **Names.** The folders are `packages/core`, `packages/video`, `packages/ui`, `packages/sidecar`; the package names are scoped (`@opsis/core`, …) so no import can resolve to an unrelated npm package. The Electron app stays at the root (`src/main`, `src/preload`, `src/worker`, `src/engine`, `src/traces`) and depends on all four.
- **Files that wait in `core`.** A `src/shared` file moved to its final package only when nothing that stays in `core` (or in the Electron app) imports it, or the packages would import each other in a circle. Moved now: to `ui` `timeline/edits`, `timeline/snap`, `workflow-edits`, `workflow-diff`, `mix/edits`, `nodes/looks`; to `video` `mix/duck` and `fonts/google-font-imports` (the table says `scripts`, but `video/fonts/google-font.ts` imports it). Waiting in `core` until phase 6 deletes it: `elements/introspect`, `fonts/plan`, `gradient`, `errors`, `ids`, `named-files`, `listener-set`, `timing`, `timeline/handles` (ui); `fonts/index`, `fonts/types`, `fonts/bundled.generated`, `math`, `guards`, `memo`, `lists`, `hash`, `chord`, `objects`, `window-styles`, `audio` (video). `nodes/icon-name.test.ts` moved to `packages/ui/src/editor`, because it scans node definitions and the editor's icon map.
- **Exports.** `video` exports `spec` (`designScaleFor`, `registerFaces`, `unregisterFaces`, `duckGain`, `duckingSpans`), `root`, and three entries that go away with the code that uses them in phase 6: `player` (`DemoTimeline`, until the preview is streamed), `capture` (what the worker's capture reads), plus `composition-id`, `fonts/google-font-imports` and `registry/framing` for the sidecar, the Vite config and the registry scripts. `core` and `sidecar` export every file; `ui` exports `nodes/looks` for `glyphs:bundle`. Every export key is a file path under `src`.
- **Imports.** `core`, `video` and `sidecar` import their own files by relative path, since other packages compile them; only `ui` keeps the `@/` alias. The registry ingest writes relative imports into installed elements, and the registry patches were rewritten to match. It now runs shadcn inside `packages/video` (its own `components.json`).
- **Dependencies.** Each package declares what it imports, at the versions the root had (`bun add` per package, `bun remove` at the root); the lockfile resolves the same versions. Installs are hoisted (`bunfig.toml`): with bun's isolated layout, Vite's pre-bundled dependencies couldn't resolve their own imports (`@floating-ui/utils` from `@base-ui/react`) from the root. Phase 1.5 went back to the isolated layout.
- **Vite.** The renderer config aliases `@opsis/core` and `@opsis/video` to their `src` folders: through `node_modules` its dependency optimizer took them for prebuilt packages and parsed their TypeScript as JavaScript, and excluding them left their CommonJS dependencies (`lottie-web`) unconverted.
- **Sidecar.** `render.ts` no longer reads the engine folder or the codec table: callers pass `browserExecutable` and the `crf` (or none). `free-tcp-port.ts` moved with it. `picture.ts` and the asset server stay in `src/worker/render` until `opsis-render` replaces them. Export as code copies `video`, `core` and the webpack override (`EXPORTED_SOURCES`, `source-layout.ts`) and reads dependency versions from every package's manifest.
- **Turbo.** `typecheck`, `lint`, `lint:fix` and `test` run per package, with root tasks (`typecheck:app`, `lint:app`, `test:app`) for the Electron app; `cacheDir` is set so a git worktree keeps its own cache. `build` is declared for the Tauri build (phase 6); no member has a build script yet.
- **Checked.** Type check, lint and the 1,280 tests (the same 172 files as before) pass; the generators (`routes`, `glyphs:bundle`, `fonts:bundle`, `db:schema`, `examples`) write the same files; the dev app and a packaged lite build run. The changelog example exports the same 1:1 file byte for byte as before the split; its 16:9 file differs in the last 75 frames, which the code before the split also does between two runs, so a byte-for-byte check needs that nondeterminism found first. The to-do example records the same take key, and its render fails the same way before and after the split (`Error loading image with src: …/glaze`).

## Phase 1.5 as built

Phase 1.5 corrected phase 1's layout before any Rust (2026-10-25, branch `feat/tauri`, still Electron). It replaces the Imports, Dependencies and Vite notes above, and the package table's `packages/ui`, `packages/sidecar` and `app` crate.

- **Apps and packages.** An app builds something and nothing imports it; a package is source an app compiles. The editor is `apps/ui` (a Vite app with its own `vite.config.ts` and `index.html`) and the sidecar is `apps/sidecar`; `packages/core` and `packages/video` stay packages. There is no `packages/ui` until a second app shares UI. The Tauri Rust code goes in `crates/`, not under `apps/`.
- **Imports.** Each member imports its own files through its `package.json` `imports`, with a named prefix: `#core/…` and `#sidecar/…` without extensions (all `.ts`), `#video/…` with extensions (`.ts` and `.tsx` share folders, and TypeScript neither completes an extensionless target nor lets Vite use an array of targets). `#/` is out: Rspack 1.7.11 rejects it ("not a valid subpath"), checked on a two-file fixture where `#lib/…` builds. Vendored registry code uses `#video/…` only where the ingest writes the import (imports that were `@/video/…` before phase 1); upstream's own relative imports stay, so the patches still fit (`applyPatches` reports every patch applied, no installed file changed). The ingest, the patches and the generators (`elements.generated.ts`, `components.generated.ts`, the Google font shims, `bundled.generated.ts`) write the same forms. Only the editor uses `@/`.
- **Dependencies.** bun's default isolated layout; `bunfig.toml` is gone. Phase 1's hoisted layout and Vite aliases worked around Forge's renderer default `resolve.preserveSymlinks: true`, which made Vite resolve linked packages through `node_modules` (parsing their TypeScript as JavaScript) and resolve dependencies from symlink paths (`@floating-ui/utils` from `@base-ui/react`); the editor's config sets it to `false`. The isolated layout showed three phase-1 mistakes, now fixed: `@fontsource/instrument-serif` belongs to the root (`fonts:bundle` reads it), `three:decoders` reads `three` from `packages/video`, and the root declares `@remotion/bundler` and `@remotion/tailwind-v4`, which the Electron worker loads outside its bundle.
- **Rspack.** The video bundle is built with Rspack (`rspack: true`, `rspackOverride` in `bundler-override.ts`, typed with `@rspack/core` 1.7.11, the version `@remotion/bundler` pins). Before switching, every registry element's middle frame (109) rendered byte-identically from a webpack and an Rspack bundle of the same tree, and neither bundle contained a `fonts.gstatic.com` URL; the bundle took 1.6 s against 11.4 s. Export as code configures Rspack in the exported `remotion.config.ts` and sets `allowImportingTsExtensions` for `video`'s imports.
- **Checked.** Type check, lint and the 1,280 tests pass; the generators write identical files; the editor build has the same 235 files (six utilities, made from words outside the editor, left the CSS: `resize`, `grayscale`, `invert`, `sepia`, `blur-in`, `text-input`); the changelog example exports the same node hash and the same 1:1 file as phase 1 from the dev app and from a packaged lite build; the exported code project bundles and type-checks.

## Decisions for the user

- **Names (decided).** `apps/ui`, `apps/sidecar`, `packages/video`, `packages/core`, and the crates above: folders `crates/<domain>`, crate names `opsis-<domain>`.

## Risks

- **Two bundlers for video code.** Rspack (through Remotion's bundler) builds `packages/video`; the editor imports `video/spec` through Vite. Keep `video/spec` free of anything Remotion-only so both resolve it.
- **Subpath prefixes.** Rspack 1.7.11 rejects `#/…`; keep named prefixes (`#core/`, `#video/`, `#sidecar/`).
