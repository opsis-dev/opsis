# Working on Demoflow

Read `README.md` for what the app does and `plans/` for planned work. This file is about changing it.

## Hard rules

**No comments. Any kind. Anywhere.** No `//`, no `/* */`, no JSDoc, no file headers, no CSS comments, in source, tests, scripts and config. If something needs explaining, the name is wrong or the function is too big; constraints that span the codebase go in this file. The only allowed comment-shaped lines are functional directives: `oxlint-disable…`, `/// <reference …>`, `@ts-…`. Check:

```bash
rg -n '^\s*//|/\*|\*/' --glob '*.{ts,tsx,mts,css}' src scripts *.config.ts -g '!src/video/elements/**' -g '!src/video/lib/**' -g '!src/video/hooks/**' -g '!src/renderer/components/**' -g '!src/renderer/routeTree.gen.ts' | rg -v 'oxlint-|/// <reference|@ts-|\*\*/|/\*\*"'
```

**File names are kebab-case** (`trace-panel.tsx`, `keycap-hud.tsx`), like the shadcn components; the code inside keeps its usual names (`TracePanel`). oxlint enforces it (`unicorn/filename-case`); the only exception is TanStack Router's `__root.tsx`. To rename, use the TypeScript rename edits (`getEditsForFileRename`, what VS Code calls on file move) so imports follow, then search for the old name in strings, configs and docs.

**Never hand-edit installed or generated code.**

| `src/video/elements/**`, `src/video/lib/**`, `src/video/hooks/**`                               | Remocn / snapcn / RemotionUI registries            | `bun run registry:ingest` (list in `scripts/registry-ingest.list.ts`)                             |

| `brand/icons/*.png`                                                                             | `brand/logo.svg` (the one source for the app icon) | `bun run brand:icons` (renders with the recording browser; ImageMagick draws the gradients wrong) |

**Dependencies go through the package manager.** `bun add`, `bun add -d`, `bun remove` only; never edit dependency blocks by hand. Always the latest release, except:

- every `remotion` / `@remotion/*` package is pinned to the same exact version (`bun add --exact`); mismatches break silently;
- `typescript` is pinned to `6.0.3` until TypeScript 7.1. Remotion's esbuild loader reads `tsconfig.json` through `typescript.sys`, which TS 7.0 does not expose, and the Remotion bundle then compiles with the classic JSX runtime. Do not patch around this; upgrade when 7.1 ships.

**Tooling:** bun is the package manager, Node/Electron the runtime; nothing ever runs under Bun's runtime (`--bun`). Every tool config is a `*.config.ts`. Dev scripts run on Node through `tsx` (`tsx scripts/x.ts`), so they import TypeScript without file extensions like the rest of the code.

**Verify with** `bun run typecheck`, `bun run lint:fix`, `bun run format:fix`, `bun run test`. The `:fix` variants fix and report the rest; do not run the non-fix variants first.

**Do not commit or push.** Leave changes in the working tree unless asked.

**Large files go to `~/.cache/demoflow-*`** (browser binaries, clones, renders); `/tmp` is for small scripts and screenshots only. Long-running processes start with `run_in_background`.

## Layout

```
src/main/      Electron main: window, menus, IPC, protocols, projects, secrets, worker host
src/preload/   contextBridge `window.demoflow`
src/worker/    utilityProcess: engine/, executors/, capture/ (Playwright), media/ (FFmpeg), render/ (Remotion)
src/engine/    Node-only: engine paths and installer (headless shell + FFmpeg), shared by main, worker, forge
src/traces/    Node-only: compressed, deduplicated Playwright trace store
src/shared/    runtime-neutral: schema/, nodes/, elements/, compile/, templates/
src/video/     Remotion root: DemoTimeline, registry/, core/, camera/ (programatic-demo), elements/ + lib/ (registries)
src/renderer/  React UI: routes/, app/, editor/, store/, components/
scripts/       registry ingest, examples, start wrapper, oxlint plugin
```

## Invariants that must not regress

**Runtime boundaries.** `src/shared` and `src/video` are imported by the Vite renderer, the worker and the Remotion webpack bundle: no `node:*`, `electron`, `playwright-core`, `@remotion/renderer` or `@remotion/bundler` there (oxlint enforces it). Node-only code lives in `src/worker` and `src/main`. `src/shared/elements` metadata never imports a component; implementations are keyed separately in `src/video/registry`.

**Every animation in `src/video` is a pure function of `useCurrentFrame()`.** No Framer Motion, `motion`, GSAP, CSS transitions or Tailwind `animate-*` (oxlint: `no-restricted-imports`, `demoflow/no-animate-class`). Randomness uses `random(seed)`; async work uses `delayRender()`.

**Nodes never generate Remotion code.** A node definition (`src/shared/nodes`) has ports, zod params and an optional pure `compile()`; executors (`src/worker/executors`) are keyed by node type. Every node with `executes: true` has an executor (tested). Compile produces a `TimelineSpec`; the single `DemoTimeline` composition renders it in both the editor `<Player>` and the worker's `renderMedia()`, so preview equals render.

**Browser nodes are virtual.** They form a `session` chain; the capture node that closes it replays the whole chain in one take.

**Params carry their own inspector UI** through zod `.meta({ description, help, widget, step, unit, labels, zeroLabel, presets, presetsLabel, showIf, advanced, hidden, pauses, timeKey })` (type `FieldMeta` in `src/shared/elements/introspect.ts`; add to existing meta with `more()`). `unit: "ms"` and `unit: "frames"` are stored as-is and shown in seconds. Widgets: `textarea`, `code`, `asset`, `target`, `secret`, `timezone`, `keys`, `datetime`, `variable`, `backdrop`, `offsets`, `spot`, `quality`, `loudness`, `transition`, `multiselect`, `color`, `sound` (built-in sounds or a project file, with a play button), `font` (project, built-in and library fonts; picking a library font copies it into the project), `boxes` (areas drawn over a frame of the upstream recording, stored as fractions of the frame). Widget names are listed in `FIELD_WIDGETS` (a registry test fails on any other); a `spot` field keeps its y in `spotYKey(name)` and shows the frame at the time in its `timeKey` param and a `target` field the picked element's role in `targetRoleKey(name)`. Plain text fields render variables as chips (`VarText`); never show `{{…}}` to a user. Fields write on every keystroke, so the Inspector wraps a focused text field in a gesture (`useTypingAsOneUndoStep`): typing until the field loses focus is one undo step.

**Node cards.** Every visible node has a `description` and a `card()` returning up to four `row(icon, text)` lines (`src/shared/nodes/card.ts`), computed from interpolated params, run results, saved sign-ins and connected inputs. Icons are lucide names typed as `NodeIconName` (`src/shared/nodes/icon-name.ts`); `NODE_ICONS` in `src/renderer/editor/icons.ts` maps every one of them, so the type check fails on a missing icon. Nodes that produce a file show a poster frame (made by `decorateArtifacts` in the worker, stored in the node's cache folder); nodes that produce a clip show a saved still once the node has been opened in the Preview panel or fed an export: the editor sends the clip's spec to `requestStill` (`src/main/stills.ts`), which queues it, waits while a run is going, and has a long-lived worker (`src/worker/render/card-still.ts`, one shared browser, 480 px JPEG of the middle frame, Fast quality) write `.demoflow/cache/stills/<sha256 of clip + settings>.jpg`; `index.json` maps node ids to their latest still and unused stills are deleted. A node that already has a still gets a new one in the background when it changes; the old one stays until it's ready. Without the engine, cards fall back to live `<Thumbnail>`s, limited to six at a time, on screen and at canvas zoom 0.55 or more.

**User-facing copy.** No library, tool or format names (Playwright, Remotion, Chromium, FFmpeg, CRF, DPR, page.evaluate…) in node titles, descriptions, field labels, badges, toasts or error messages; the exceptions are the Remotion licence notice (Settings and the first-run screen), which must name it, and Settings → Licences and About, which list what Demoflow includes by name; technical settings go under `advanced`. Sentence case. Durations in seconds. Browser nodes are "actions", never "steps". Elements are described in words (`elementName`). The node's name (`node.label`) is also its camera, chapter and caption label. Categories keep their internal ids; display names come from `CATEGORY_LABELS`. Registry element descriptions come from the registry item JSON at ingest time, with overrides in `DESCRIPTIONS` (`scripts/registry-ingest.list.ts`). Element defaults never name a library and never load from the internet: neutral copy and `app:` placeholders (`public/placeholders`, `public/backdrops`) go in `NEUTRAL_DEFAULTS` / `NEUTRAL_FIXED_PROPS`, and the ingest fails on any default that breaks this, for every registry. `src/shared/nodes/card.test.ts` enforces descriptions and the banned words.

**Editor panels.** The node list, Inspector and bottom panel collapse (Ctrl/Cmd+B, Ctrl/Cmd+Alt+B, Ctrl/Cmd+J, also in the View menu and the top bar); `src/renderer/editor/panels.ts` owns their handles, open state and the active tab, and layouts persist through `useDefaultLayout`. A collapsed node list becomes a 44 px category rail with popovers. The bottom panel is **tabs**, not a split row: Preview, Timeline, Mixer, Run (Ctrl/Cmd+1…4, `dock.tsx`). Any tab opens in its own window (`src/main/panel-windows.ts`, route `#/panel/<name>?project=…`, bounds saved in `<userData>/panel-windows.json`); closing that window docks the tab back. The Preview tab stays mounted while hidden so playback keeps running.

**View state is per project, on this computer.** The active tab, panel sizes and collapsed panels, timeline ruler and snapping, and Fast/Exact preview are saved in local storage keyed by the project folder (`src/renderer/store/view-prefs.ts`, loaded by `loadViewState` when a project opens; layout ids include the folder). A project with nothing saved opens with the defaults (Preview tab). Pop-out window bounds stay global.

**Starting and closing.** Settings → Starting and closing: on start show the start screen, open the last project, or open New project (once per app launch, `__root.tsx`); and "Ask before closing". Closing or quitting the main window goes through `src/main/exit.ts`: it asks the renderer to show `ExitDialog` (in-app, never a native dialog). With asking on: "Are you sure you want to exit?" with "Don't ask again". With it off, it only appears when work is unfinished (a run, engine setup, font download, unsaved changes), without the checkbox. Unfinished work is always listed and the button becomes "Close anyway"; closing flushes the pending save and stops the run. Wrap new long main-process work in `track(label, promise)` so it's listed. The dialog answers `closeShown` as soon as it receives the request; if nothing does within 2 s (the window crashed or is showing an error), main saves and closes without asking, so a broken window can always close. Render errors show `ErrorScreen` (`src/renderer/app/error-screen.tsx`, the router's `defaultErrorComponent`, so every route has its own boundary and the root, the exit dialog and the title bar stay up): the app bar, Try again, Reload window and the message under Details. Components that read a node by id must handle it being gone: the Inspector's fading-out panel renders once more after a delete.

**Settings is its own window** (`src/main/settings-window.ts`, route `#/settings?page=<page>`, bounds in `<userData>/settings-window.json`), opened by `openSettings(page?)` from the menu, Ctrl/Cmd+, and any Settings button; it closes with the main window. A sidebar picks the page (`src/renderer/app/settings/`). Its app bar has no menu; menu shortcuts pressed there go to the main window (`sendMenuToEditor`). Settings are written with `patchSettings` (one section at a time, so windows never overwrite each other) and every window follows them through `useAppSettings` (`src/renderer/store/app-settings.ts`), which main keeps current with `settingsChanged`. Saved results (clear cache) belong to the project, in the project Inspector.

**Projects folder.** New projects are suggested in `settings.projects.lastDir` (the last place one was created) or else the default folder: `settings.projects.defaultDir`, empty meaning `~/DemoflowProjects` on every OS, like JetBrains' `~/IdeaProjects`. Changing the default clears `lastDir`. Open project starts in the default folder. The New project dialog shows the folder it will create (`projectFolderName`, `joinFolder` in `src/shared/project-folder.ts`); started from a template card, it shows only that template with Change.

**The project file can change under the app.** `openProject` returns the file's `version` (a hash of its text), kept as `fileVersion` in the workflow store. Every save sends it (`saveWorkflow(dir, workflow, base)`, `src/renderer/editor/save.ts`); main refuses to write when the file on disk has another version and returns that version instead. Main watches the open project's file (`watchProject`, the folder is watched because saves replace the file) and ignores its own writes. With nothing unsaved the editor loads the outside change as one undo step and says so; with unsaved edits, or when a save is refused, `DiskChangeDialog` asks: Load the file (undoable) or Keep mine (saves over it). Nothing saves while that question is open. Always save through `save()`.

**Local API.** Off by default; Settings → API switches it (`settings.api.enabled`, global and persistent, shown as an API badge in every app bar). `src/main/api.ts` serves plain HTTP on `<userData>/api.sock` (mode 0600; a stale file from a crash is replaced, a live one from another copy of the app is left alone and reported) or the named pipe `\\.\pipe\demoflow-api-<user>` on Windows, never on a TCP port. Without an open project it answers `/openapi.json`, `/status`, `/nodes`, `/nodes/{type}`, `/validate` and `/open`; everything under `/project` needs the open project and goes to the editor window (`apiRequest`/`apiReply`, `src/renderer/editor/api-bridge.ts`) so each request is one store update: one undo step, autosaved, mirrored to other windows. `/open` waits until the new editor has registered (`setEditorApi` wakes waiting requests). The socket opens before the window has loaded, so main forwards a request only once the editor window's preload reports its listener (`apiListening`), waiting up to the same 20 s; a reload or a closed window answers the requests in flight at once. Run events also stream on `/project/run/events`. The OpenAPI document (`src/shared/api/openapi.ts`) stays small (about 70 KB); node settings schemas come from `/nodes/{type}` (`z.toJSONSchema`, the full catalogue is about 400 KB). Validation is `checkWorkflow`/`workflowProblems` (`src/shared/api/check.ts`), the same checks the editor shows. Routes live in `src/main/api-routes.ts` and request bodies are zod schemas in `src/shared/api/bodies.ts`, which `openapi.ts` turns into the documented bodies; add an endpoint to `openapi.ts` whenever you add a route.

**Canvas.** `settings.editor.canvasMode`: `mouse` (the default: wheel zooms, drag pans) or `touchpad` (two-finger scroll pans, pinch zooms), chosen in the canvas toolbar and remembered for every project. The minimap shows or hides from the toolbar, View → Minimap or Ctrl/Cmd+Shift+M, per project (`minimap` view pref). The React Flow attribution is hidden (`proOptions.hideAttribution`); the library prints a console note asking for a Pro subscription when you do. The workflow store owns node positions and the UI store owns selection; React Flow's own per-node state (measured size, a drag or resize in progress) lives only in `useFlowNodes` (`src/renderer/editor/use-flow-elements.ts`), merged over the store's nodes, so a drag writes one position at drag stop instead of one undo step per frame. The node list's group titles stay pinned while their group scrolls (sidebar list only).

**Windows share one editor.** The editor window owns the project store and undo. Panel windows mirror it over the `demoflow-sync` BroadcastChannel (`src/renderer/app/sync.ts`): edits go back as `replace`/gesture messages (`mirrorEditsTo`), menu commands are forwarded, run events are relayed, and the playhead follows whichever window hosts the Player (`src/renderer/store/playback.ts`). The live recording port goes to the Run window when it's open; whichever window receives live frames relays them on `demoflow-live`. IPC accepts calls from the editor, its panel windows and the Settings window only; window roles act on the calling window. Request/response calls are declared once in `INVOKE` (`src/shared/ipc.ts`, keyed by the `DemoflowApi` method): the preload builds its wrappers from it and the handler table in `src/main/ipc-handlers.ts` must cover every entry, which the type check enforces. Engine set-up progress, settings changes and API status go to every app window.

**Timeline.** `flattenSpec` (`src/shared/timeline/flatten.ts`) turns the compiled spec into bars on lanes (greedy packing in drawing order), audio bars, transitions and action marks, mapping frames through trims, loops and speed remaps. Edits never touch the spec: compile records `handles` (`move`, `trimStart`, `trimEnd`, `speed`, `volume` as `ParamRef`s) on items, and container children carry a `slot` (container node + port). `src/shared/timeline/edits.ts` applies an edit to the owning setting or, when nothing owns it, inserts a named node ("Delay from timeline", "Trim from timeline", "Speed from timeline", split parts) at the slot edge or right after the clip. Every handle has a round-trip test in `edits.test.ts`; add one when a node gains a handle. Drags call `beginGesture`/`endGesture` so a drag is one undo step. Keyframes are an `envelope` param (`visualEnvelope()`/`audioEnvelope()` in `params.ts`, frames local to the item) shown on the timeline and in the Inspector (`envelope` widget); they compile onto `TimelineItem.envelope`/`AudioItem.envelope` and stay pure functions of the frame.

**Mixer.** Mix settings are `workflow.mix` (`src/shared/mix/types.ts`): a strip per channel (keyed by node id: Music, each Sound effect, each clip with sound), buses (Music, Effects, Clips built in, plus user buses) with sidechain ducking, and a master with EQ, compressor, limiter and loudness target. `normalizeWorkflow` prunes channels of deleted nodes. `buildMixPlan` (`plan.ts`) and the FFmpeg filter graphs (`graph.ts`, tested by string) are pure; `src/worker/mix/render.ts` renders channel, bus and master stems into `.demoflow/cache/mix/` (content-hashed, recent plans kept), with per-frame peak/RMS, compressor gain reduction and EBU R128 loudness. Exports always play the master stem (`withMasterStem`): `renderExecutor` renders the picture once without sound into `.demoflow/cache/pictures/<pictureKey>` (the key leaves out the spec's audio, mix and asset address; recent pictures kept) and adds the master stem with FFmpeg (`muxArgs`, `src/worker/render/picture.ts`), so a mix or sound-only change never renders the picture again. Bump `PICTURE_VERSION` when a picture-affecting change isn't in the spec; the preview plays the latest stem for its film and shows "Updating sound" while a new one renders, applying mixer drags at once through a temporary Web Audio insert (`AudioInsert` in `preview-composition.tsx`). Without a stem (no engine yet) the preview falls back to per-sound gains (`applyMixLevels`). Mute and solo are saved and apply to exports. Strip selection is the editor's node selection (Ctrl/Cmd-click toggles, Shift-click takes the range in strip order); a strip menu on a selected strip applies to every selected strip in one `setMix` call, so it is one undo step. Bump `MIX_VERSION` when stem output changes.

**Run state.** Run events go through one pure reducer, `applyRunEvent` (`src/shared/run-progress.ts`), in the run store and in main, which keeps the active run's progress so `runStatus` can return it; an editor that opens the project mid-run calls `resume(progress)`, never a fresh start. A run clears status, progress and errors only for the nodes it includes (`run:start` `nodeIds`), so a **Run this** never hides an earlier failure; `run:done` names `failedNodeIds` and `skippedNodeIds` apart, and the panel shows each failed node as a link. The panel's exports list comes from the results of every `output.*` node, newest first (`exportedArtifacts`), not from the last run's `outputs`.

**Chapters in exports.** `filmChapters(spec)` (`src/shared/timeline/chapters.ts`) reads the Chapter action marks from `flattenSpec`, starts the first at 0:00 (or adds an "Intro" chapter when the first starts 10 s or more in) and merges chapters under 10 s into the one before, YouTube's rules. Export video writes them as FFmpeg chapter metadata in the finishing copy (`finishArgs`, with the web-ready move), so a chapter change never renders the picture again; GIFs get none. The optional `.youtube-chapters.txt` needs at least three chapters.

**Drag action.** `browser.drag` drags onto an element (measured again after the press, failing when it isn't on screen), by an offset, or along a path; the smooth method presses, waits `holdMs`, nudges 6 px (pages start drags past a threshold) and walks the points with the same 8 ms sampler as glides (`walk`, pure curves in `src/worker/capture/drag-path.ts`; glides must keep their exact samples). The action logs `tDown`, `t` (the release), `path` (at most 64 points) and `drop`; `toClickLog` makes one camera event covering both ends when they fit in half the window, else a pick-up and a drop event, and `cursorAt` keeps the arrow pressed until `tUpMs`. The baked cursor follows `dragover` too. The picker's Shift-click returns a spot as `x, y`, in a window sized to the take's browser.

**One engine, two editions.** Capture (Playwright) and render (Remotion) launch the same Chrome Headless Shell: whatever `ensureBrowser()` picks for the platform at Remotion's pinned `TESTED_VERSION` (Remotion's own build on Linux x64/arm64 and Apple Silicon, Google's Chrome for Testing elsewhere). FFmpeg and ffprobe come from the ffmpeg-static GitHub release pinned in `src/engine/paths.ts`. `ensureBrowser()` can only download next to a `package.json`, so the installer downloads into `engine/.download/` and moves the shell to `engine/chrome-headless-shell/`. The engine lives in `resources/engine` (full edition, staged by `forge.config.ts`) or `<userData>/engine` (lite edition and dev, installed from Settings). `DEMOFLOW_EDITION=lite bun run make` builds without it. Never fall back to Playwright's own browsers, system Chrome or Electron's Chromium for capture or render.

**Capture timing comes from frames, not markers.** Screencast `onFrame` JPEGs go into `FrameEncoder` through `offer`, which never waits: Chrome sends the next frame only after `onFrame` returns, so waiting on the encoder loses any page change painted during an encoder stall. Encoder errors surface at `finish`. The encoder writes a constant-rate stream from the first frame after the setup steps; action timestamps share that origin. Live frames for the editor PiP are the same frames, throttled to the live fps setting, sent over a dedicated MessagePort straight from the worker to the renderer.

**Interactive browsing happens in Electron windows**, never in headed Playwright: the element picker and Login once open sandboxed `BrowserWindow`s with their own session partition (`src/main/browser-windows.ts`); login state is converted to Playwright storage-state JSON and encrypted with `safeStorage`. A Login once node has no edges: the runner (`loginDependencies` in `src/shared/graph.ts`) schedules it before any capture whose Session's `storageState` names its secret, and only when that secret is not saved yet. The login window finishes on URL change or selector even in single-page apps (`did-navigate-in-page`, selector polling).

**Traces** are recorded per capture unless retention is `off`, ingested into `.demoflow/traces` (zstd for text, raw for images, content-addressed blobs shared across runs), pruned by the retention setting. Blob files keep the entry's extension (`<sha>.jpeg`, `<sha>.zst`) so screenshots load straight through `demoflow-file://`. The Trace tab in Replay (`TracePanel`) is our own shadcn UI over `readTrace()` (`src/traces/model.ts` parses `trace.trace`/`trace.network`); never embed Playwright's Trace Viewer or open a local server for it. The driver wraps each step in `tracing.group(label)` and the manifest's `groups` maps those groups back to node ids in order.

**Nothing uses the internet unless the user asks.** The app works offline. Anything that needs the network (setting up the engine, getting fonts online) sits behind a button and asks first, and what it downloads is saved locally (`<userData>/engine`, `<userData>/fonts`). Never load fonts, images, scripts or sounds from a remote URL at preview or render time. User-facing copy never names the services behind it.

**Fonts.** 16 families (Latin, all weights, italics where they exist, about 1 MB) are bundled from Fontsource into `public/fonts/bundled`. The user's library lives in `<userData>/fonts` (`library.json` + files, served as `demoflow-file://fonts/`) and is filled from font files or ZIPs (`src/main/fonts.ts` reads names, weights and italics with `fontkit`; `planFontFiles` keeps one file per style, variable and woff2 first), fonts installed on the computer (`queryLocalFonts`), or Fontsource online. A project copies the library fonts it uses into `assets/fonts/<id>/` and lists them in `settings.fonts.families`, so it works anywhere. `settings.fonts` also holds the roles `main`, `heading` (empty = main) and `code`. In the video, `FontProvider` registers fonts through `src/video/fonts/registry.ts`: `df-main`, `df-heading` and `df-code` point at the role fonts, `Inter` follows `main` and `JetBrains Mono` follows `code`, so every element follows the project fonts; per-node fonts (the `font` widget, stored as a family name, turned into a CSS stack by `fontStack`) load by name. Elements' `@remotion/google-fonts/<Name>` imports are redirected in both bundlers (Vite plugin in `vite.renderer.config.ts`, webpack hook in `webpack-override.ts`) to the generated modules in `src/video/fonts/google/`, which load the bundled copy; `fonts:bundle` fails if an element imports a font that isn't bundled. Export cache keys include the project settings, so changing fonts re-exports.

**Registry elements load lazily.** `components.generated.ts` holds `import()` loaders; `DemoTimeline` waits on `delayRender` until an element's module is loaded, so unused elements never run their side effects (font loads).

**Asset refs are host-independent.** Specs hold `project:<relative path>` or `app:<public path>`. The editor resolves `project:` through `demoflow-file://project/`, renders through the worker's 127.0.0.1 asset server, `app:` always through `staticFile()`.

**Cache keys.** A node hash is `sha256(ENGINE_VERSION, type, interpolated params, upstream hashes)`. Bump `ENGINE_VERSION` in `src/worker/engine/cache.ts` whenever an executor's output format changes. Every key that picks a file on disk is a sha256 (`versionedHash`, `src/engine/hash.ts`); the 64-bit `lookupKey` (`src/shared/hash.ts`) only matches values in memory, such as a mix plan to its result. Cached JSON is read through `readJson(file, schema)` (`src/engine/json.ts`), never trusted as-is.

**No old formats.** Nothing has been released, so there is no migration or fallback code for older project files, settings, engine folders or caches: when a format changes, change it everywhere, write `examples/` again (`scripts/write-examples.ts`) and delete local test projects.

**Packaging.**

- Forge's Vite plugin ships only `.vite/`; anything the worker loads at runtime and Vite leaves external must be staged in `forge.config.ts` `packageAfterCopy` (playwright-core, the compositor package).
- The Remotion bundle is prebuilt at package time; a packaged app never calls `bundle()`. `@remotion/bundler` and `@remotion/tailwind-v4` are imported lazily for that reason.
- `binariesDirectory` points at the compositor in `app.asar.unpacked`; all renders pass the Remotion licence key from Settings (`free-license` when empty).
- Remotion ignores tsconfig `paths`; the `@` alias is mirrored in `src/worker/render/webpack-override.ts`.
- CI: `.github/workflows/build.yml` runs typecheck, lint, format and tests, then `make` for `full` and `lite` on `ubuntu-latest` (deb + AppImage), `windows-latest` (Squirrel), `macos-latest` and `macos-26-intel` (zip), uploading `out/make/**`. The engine and the Chromium credits are cached per OS and arch for both editions; the lite job checks `resources/engine-licences/LICENSES.chromium.html`. Check the workflow with `actionlint`.
- Licences: the full edition stages `resources/engine/LICENSES.chromium.html`, the `chrome://credits` page of the full Chrome for Testing build matching the bundled headless shell's version (`src/engine/chromium-credits.ts`, cached in `~/.cache/demoflow-chromium-credits`); never ship the engine without it. The lite edition stages the engine too, only to make that file, and ships just the file in `resources/engine-licences/`; at startup and after engine setup `completeLicences` (`src/engine/licences.ts`) copies it into an engine folder that lacks it, so Settings → Licences can list the recording browser. In development, `bun run engine:licences` writes it from the dev engine (it downloads the matching Chrome for Testing build, about 400 MB unpacked, into the cache). Renders pass `remotionLicenseKey(env)`: the Settings key, or `"free-license"` when empty.
- Build entries need unique basenames (`main.ts`, `preload.ts`, `worker.ts`): Forge names outputs `<basename>.cjs`.
- Icons: `brand/logo.svg` is the source; `brand/icons/` (16–1024 px PNGs) ships as an extra resource for the window icon, the deb uses the 512 px PNG, the AppImage the SVG plus PNG sizes. Windows `.ico` and macOS `.icns` aren't made yet.
- Linux: `bun run make -- --targets deb,AppImage` (the RPM maker needs `rpmbuild`). `--targets` takes maker names; package names make Forge build fresh makers without our options. `DEMOFLOW_OUT_DIR` moves Forge's output out of the repo, e.g. to `~/.cache/demoflow-build`. The deb installs `chrome-sandbox` setuid root, so it keeps the sandbox. An AppImage can't (its mount is `nosuid`), and Ubuntu 24.04+ blocks unprivileged user namespaces, so the AppImage starts through `demoflow-launcher` (`scripts/appimage-launcher.sh`, copied in `postPackage`), which adds `--no-sandbox` only when `unshare --user` fails. The flag can't be added from `main.ts`: Chromium aborts before it runs.

**Other shapes.** Exports and the Preview's shape switcher (per project, `previewShape`) size the spec with `variantSize`. A recording in a shape narrower than itself keeps its own shape inside the frame (`containBox`) and the camera zooms harder (`zoomBoost`, `narrowPose`): it never rests fully zoomed out and aims at the cursor between actions. In a narrower shape the camera plans for that frame (`tuning.narrow`): `frameFor` fits each target to the frame's width, centred, up to the boosted maximum. The full-page styles (Proof, Ledger) show the whole page in any other shape (`NarrowBleedClip`) over a blurred copy of the footage, with that same camera only when narrower. Window styles in wider shapes, and the `center`/`fit` choices, keep the old crop or bars. Overlays size by the long side (`overlayScale`) and keep clear of `shapeInsets`; outside landscape, lower thirds move to the top so captions own the bottom. A Layers node with **Keep this layout in other shapes** wraps its layers in a group with `design` (the project's size), drawn scaled to fit, for marks placed over a picture. Everything is in `src/video/core/frame.ts`, except `containBox`, which lives in `src/video/core/still-layout.ts` (no Remotion imports, so the worker can use it) and also sizes screenshot windows.

**Transitions.** A transition overlaps the clips by its length unless **Keep every clip whole** is on (`TransitionRef.hold`): then `sequenceClips` holds the outgoing clip's last frame and the incoming clip's first frame for the transition (group `remap`) and delays the incoming clip's sound, so no clip loses screen time. Cards warn when a transition covers more than 40% of a clip (`coverRow`, fed `inputFrames`), when it is squeezed below 40% of its designed length, when Fit length cuts or speeds a lot, and when an element is shorter than 60% of its usual length; the Timeline outlines heavy transitions (`TransitionMark.covers`). A Sequence's `cuts` give the cut before a port (`before`: `in2`…`in6`, so connecting other clips never moves it) its own transition, length and hold (`cutsFor`, last entry for a port wins, entries for empty ports are kept and ignored); `splitBar` splits inside any Sequence, shifting later ports and cuts by one and joining the halves with a plain cut. Transition marks carry the `slot` that owns them, and clicking a mark's label on the Timeline selects that node.

**Ports that take several connections.** A `many()` input port (Add sound's Sounds) accepts any number of edges; compile concatenates their sound. A Sound effect with **On an action** stores the action's node id; Add sound places it at that action's mark in the clip (`anchorSounds`, via `flattenSpec`), plus an offset that may be negative.

**Window frames.** Auto zoom's `frame` (none, macOS, Windows, Linux) with `frameTheme` and `addressBar`, and Device frame's browser `windowStyle`, draw the title bar in `WindowFrame`; the address bar shows the take's first page address. New Device frames take the computer's OS style (`hostDefaults` in the workflow store).

**Worker temp folders.** Every worker (`spawnWorker`, `src/main/workers.ts`) gets its own temp folder, `<userData>/tmp/<app pid>-<kind>-<id>` (a run's id is its run id), passed as `TMPDIR`, `TEMP` and `TMP`, so everything the render library, the recording browser and the development bundle put in the system temp folder lands there. The folder is deleted when the worker exits for any reason, and at start `clearStaleWorkerTemps` deletes folders whose app process is gone. Never write intermediates to `os.tmpdir()` from main.

**Renders use one tab.** `renderTimeline` passes `concurrency: 1`. With Remotion's default (half the cores) the shader backgrounds fail to get a WebGL context ("WebGL is not supported") once a few tabs draw them at once, and on a 20-core machine one tab was also the fastest: 220 shader-heavy frames took 21.8 s with one tab, 32.8 s with four, 44.3 s with six; 300 recording frames took 28.5 s, 33.0 s and 35.6 s with one, two and four. Measure again before raising it.

**Screenshots.** The Screenshot node captures through `Page.captureScreenshot` with a clip `scale` from `captureScale` (`src/video/core/still-layout.ts`): enough pixels to draw the shot at the largest export (twice the project size), never below the page's pixel ratio, capped by a surface budget for very large regions. Its image carries the region's size, that scale and, for one element, the element's box inside the padded region; `StillElement` lays it out with `windowLayout` (the shot's own shape; a page more than 1.5 times taller than the frame's shape takes the frame's shape and is cut only at the bottom), `cutoutLayout` (the element fitted, at most 1.5× the captured pixels) and `bleedLayout` (covers the frame, keeping the top).

**Preview quality.** The editor preview defaults to Fast: `TimelineSpec.quality = "fast"` makes `RecordingClip` play the 960 px `recording.preview.mp4` (made by the Record executor, keyframe every half second) and skip camera motion blur, whose 8 samples each decode the full recording. Exact matches the export; renders never set `quality`, so they are always exact. Card thumbnails always use Fast.

**Audio.** Built-in sounds are CC0 files in `public/sfx`, listed in `src/shared/sounds.ts` (label, `app:` ref, length) with credits in `THIRD_PARTY_NOTICES.md`; never add a sound without a checked free licence, and never link to a remote sound at render time. Ducking is a bus setting in the Mixer: rendered stems use `sidechaincompress`; channels shorter than the bus's `ignoreShorterMs` never key it (`duckKeysFor`); the no-stem fallback turns the key channels into spans (`src/shared/mix/duck.ts`, `AudioItem.duck.keys`) and lowers the bus per frame. Sound effects carry `role: "effect"` and their natural `lengthFrames`. A `keepMusic` sound effect never keys the ducking.

**Editor look and motion.** Panels, menus and the top bar sit on `bg-sidebar`; the canvas and page backgrounds on `bg-background`; colours are dark zinc greys (hue 286, slight colour, never pure black or white; panels about `#17171B` like Tailwind zinc-900, canvas `#101013`) and only change through the tokens in `src/renderer/index.css` (the window `backgroundColor` in `src/main/app-windows.ts` matches the canvas). Editor animation uses `motion` through the small components in `src/renderer/app/motion.tsx` (`MotionProvider` respects reduced motion). Motion Primitives registry components are installed only when they pass the type check as-is (today: `text-shimmer`); otherwise write a small equivalent in `motion.tsx`. `motion` stays banned in `src/video` and `src/shared`. Pressed toggles and toggle-group items use `--toggle-on` (and `--toggle-on-border` for outline groups), with unpressed ones in the muted text colour, set once in `index.css` because the installed toggle's own pressed colour barely shows on panels; a toggle with its own pressed colour (Mixer mute and solo) sets `data-custom-pressed`. Run success is the `--success` token: the Run panel's checks and the node card's Done border, which `flow-node.tsx` draws itself because the installed status indicator's success border is a plain Tailwind colour. Vertical separators in a centred row need `data-vertical:self-center`, since the separator stretches by default.

**Animation names are global.** React Flow UI's `node-status-indicator.tsx` injects `@keyframes spin` (with a −50% translate) while a node runs, so Tailwind's `animate-spin` is remapped to `icon-spin` in `src/renderer/index.css`. Never name a keyframe `spin`.

**One title bar.** The window has no system title bar. macOS uses `titleBarStyle: "hiddenInset"` (traffic lights inside our bar, native menu in the system menu bar); Windows and Linux use a frameless window (`frame: false`) with no native menu; the window buttons are ours (`WindowControls`: minimize, maximize/restore, close through the `minimize`/`toggleMaximize`/`close` window roles, icon following the `windowState` messages from main), and `WindowBorder` draws a 1 px edge while the window is neither maximized nor full screen. Never go back to `titleBarOverlay`: its buttons and border don't match the app. Every screen renders `AppBar` (`src/renderer/app/app-bar.tsx`): the `app-drag` utility makes it the window's drag handle and every control inside it `no-drag`; on Windows/Linux it shows the in-app menu (full Menubar from 1280 px, one Menu button below). Menus come from one list, `appMenu()` in `src/shared/menu.ts`, used by the native macOS menu and the in-app menu; `useMenuShortcuts` handles its accelerators in the page on Windows/Linux (leaving cut/copy/paste/select-all/undo/redo to text fields while one is focused), roles go to `runWindowRole` in main, and navigation commands are handled once in the root route.

**Renderer hosting.** Hash history only. The packaged UI is served from `demoflow-app://app/`; its CSP is a response header set by the protocol handler, never a `<meta>`, because Vite's dev React-refresh preamble is inline.

**Linux dev sandbox.** `bun start` runs `scripts/start.ts`, which adds `--no-sandbox` on Linux in development only (AppArmor blocks unprivileged user namespaces and `chrome-sandbox` is not root-owned in `node_modules`). Packaged builds keep the sandbox.
